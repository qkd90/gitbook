# 手机安卓端

## 章节定位

本章节记录 Android Debug Bridge（ADB）与安卓机器人设备控制相关内容，面向移动端联调、自动化测试、设备管理和现场排查。当前核心资料是一份覆盖连接、应用、交互、日志、设备信息和恢复操作的 ADB 指南。

适合在已获得设备授权的前提下，快速确认设备状态、安装/调试应用、抓取复现证据并完成基础的设备控制。

## 推荐实践路径

1. **确认连接**：打开设备调试授权，执行 `adb devices`；多设备并存时固定使用 `-s 设备号`。
2. **确认现场状态**：先截图或录屏，再记录设备型号、系统版本、当前前台页面和网络信息，避免在不清楚页面状态时直接操作。
3. **完成应用联调**：安装或启动目标应用，按需清理测试数据、调起 Activity/Service，使用输入、点击、滑动等命令复现流程。
4. **收集问题证据**：拉取截图/录屏，按包名、Tag 或级别过滤 `logcat`，必要时补充进程、内存、网络和文件信息。
5. **形成可复现记录**：整理设备序列号（必要时脱敏）、系统版本、应用版本、操作步骤、命令、现象和日志时间范围。

## 常用操作闭环

| 场景 | 先做什么 | 需要保留的结果 |
| --- | --- | --- |
| 设备无法识别 | 检查 USB 调试、驱动、数据线、授权弹窗和 `adb devices` | 设备状态与连接方式 |
| 应用无法安装或启动 | 核对目标设备、APK、包名和前台 Activity | 安装输出、应用版本、启动现象 |
| 自动化动作失败 | 先截图确认页面，再执行点击/滑动/输入 | 操作前后截图、坐标/文本和日志 |
| 线上或现场异常 | 按时间范围过滤日志，并补充设备/网络信息 | 复现步骤、logcat、截图/录屏 |
| 多台设备并行调试 | 每条命令明确指定 `-s 设备号` | 设备与操作结果的对应关系 |

## 使用边界与风险

- 仅操作已授权的测试、机器人或个人设备；设备标识、日志、截图和应用数据可能含有敏感信息，导出和共享前需脱敏。
- 清除应用数据、修改系统设置、重挂载分区、刷机、关闭安全机制等操作会改变设备状态，应先备份并确认影响范围。
- 无线调试、root、Recovery/Fastboot 和安全相关命令应在明确设备型号、系统版本和恢复方案后执行。
- 自动化排查优先做可逆操作：观察、截图、日志、文件拉取，再考虑卸载、清数据或系统级修改。

## 后续维护方向

- 新增设备指南时注明 Android 版本、设备类型、连接方式和是否需要 root。
- 常见问题应写清“现象、检查顺序、命令、预期输出、恢复方式”，不要只给出破坏性命令。
- 可将高频联调流程整理为脚本，但脚本应显式接收设备序列号和应用包名，避免误操作其他设备。
