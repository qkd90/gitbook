# 安卓玩机

## 章节定位

本章节记录个人安卓设备的 Bootloader 解锁、原厂镜像提取、Magisk Root、系统更新和救砖相关实践。现有资料以小米手机为例，核心目标是让每一步都有设备/版本匹配、可验证结果和可恢复方案。

这类操作会改变系统完整性和设备数据，仅建议在备用设备、已备份数据且已确认机型兼容的前提下进行。企业受管设备、主力机或无法恢复的设备不应按本文档直接操作。

## 推荐操作路径

1. **先判断是否真的需要 Root**：阅读 Root、刷机和 Magisk 的作用与限制，确认目标功能不能通过普通系统设置或 ADB 完成。
2. **建立恢复能力再开始**：完整备份数据，确认型号、系统版本、Bootloader 状态、强制关机方式、进入 Fastboot 的方式，以及原厂恢复包是否可用。
3. **只使用严格匹配的原厂镜像**：镜像必须与设备型号和当前系统版本对应；先按文档试用原厂镜像并确认设备可正常启动。
4. **解锁后修补、再试用**：完成 Bootloader 解锁后使用 Magisk 修补目标镜像，先试用修补镜像、验证系统功能，再确认安装。
5. **把更新和救砖纳入日常维护**：系统更新前重新确认镜像与修补流程；发生异常时先按模块、系统损坏等情形选择可恢复的救砖路径。

## 每个阶段的最小交付物

| 阶段 | 必须确认 | 应保留的记录 |
| --- | --- | --- |
| 准备 | 机型、系统版本、数据备份、恢复包、ADB/Fastboot 可用 | 版本信息、备份位置、恢复步骤 |
| 解锁 | OEM 解锁状态、账号/设备条件、清空数据影响 | 解锁结果与首次启动状态 |
| 原厂镜像验证 | 镜像与版本匹配、设备能正常试用启动 | 原厂镜像来源、校验信息、验证结果 |
| Magisk 修补 | 修补目标与设备分区匹配 | 修补文件标识、修补前后版本 |
| 安装与维护 | 启动、基础功能、后续更新/救砖路径 | 安装结果、异常现象和恢复记录 |

## 关键风险与边界

- 解锁 Bootloader 通常会清除数据；刷错镜像或分区可能导致无法启动、无法 OTA 或需要完整恢复。
- Root 可能导致支付、银行、企业管控和安全类应用异常，系统完整性和保修也可能受影响。
- 不要把其他机型、其他系统版本、其他分区的镜像或命令直接套用到当前设备。
- 不公开分享账号、解锁凭据、设备标识、备份中的个人数据或任何私密文件。
- 遇到开机循环、无法进入系统或不确定分区类型时，优先停止写入操作，依据原厂恢复包和已记录的版本信息处理。

## 后续维护方向

- 新增玩机记录时标注设备型号、系统版本、分区类型、所用镜像来源和操作日期。
- 每个高风险步骤同时补充“成功时的预期现象”和“失败时的恢复入口”。
- Root、刷机和系统更新文档应随设备/系统版本变化复核，不将旧版本命令视为通用方案。
