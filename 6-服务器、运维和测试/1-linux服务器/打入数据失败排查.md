# 打入数据失败排查

## 问题背景

数据打入失败通常出现在日志采集、Kafka 消费、脚本入库、定时任务或接口同步链路中。现象可能是脚本执行成功，但前端页面没有数据；也可能是 Kafka 有消息但数据库没有落库。

## 排查链路

```text
数据源
  ↓
采集脚本或接口
  ↓
Kafka / MQ
  ↓
消费服务
  ↓
数据库
  ↓
前端页面
```

排查时要沿链路逐段确认，不要只看最后页面。

## 查看 Kafka 日志

示例：

```bash
tail -f /data/log/20210113/alarm_branch/log/alarm_branch_0_message.log
```

重点关注：

- 是否有消息写入。
- 是否有序列化、反序列化错误。
- topic、partition、consumer group 是否正确。
- 消费位点是否推进。

## 查看服务状态

```bash
systemctl status sf
```

如果服务异常，再查看详细日志：

```bash
journalctl -u sf -f
```

或者查看应用日志：

```bash
tail -n 200 /data/log/sf/app.log
grep -i "error" /data/log/sf/app.log
```

## 常见原因

### 1. 序列号或主键问题

脚本执行成功但前端无数据，可能是序列号、主键或业务 ID 不符合查询条件，导致数据写入了错误位置或被后续逻辑过滤。

检查：

- 主键是否重复。
- 序列是否递增。
- 业务 ID 是否和页面查询条件一致。
- 数据是否写入目标表。

### 2. 时间范围不匹配

页面通常按时间筛选，如果打入数据的时间字段不在查询范围内，前端会显示为空。

检查：

```sql
SELECT MIN(create_time), MAX(create_time), COUNT(*)
FROM target_table;
```

### 3. 数据状态被过滤

常见过滤字段：

- `is_deleted`
- `status`
- `tenant_id`
- `dept_id`
- `data_type`

确认页面查询 SQL 的过滤条件，再回查数据。

### 4. 消费服务没有运行

Kafka 有消息但数据库无数据时，检查消费者服务：

```bash
ps -ef | grep java
systemctl status <service-name>
```

### 5. 数据库连接或权限异常

查看应用日志中是否有：

- connection refused
- timeout
- access denied
- deadlock
- duplicate key
- lock wait timeout

## 最小验证 SQL

```sql
SELECT COUNT(*)
FROM target_table
WHERE create_time >= '2026-01-01 00:00:00';
```

如果页面按用户或租户过滤，要加上对应条件：

```sql
SELECT *
FROM target_table
WHERE tenant_id = 'xxx'
  AND user_id = 'xxx'
ORDER BY create_time DESC
LIMIT 10;
```
