# 数仓项目

## 章节定位

本章节用于沉淀数据仓库项目的整体架构、分层设计、数据流转、任务调度、质量校验和指标建设经验。当前目录中已有项目架构图，可作为后续补充业务链路和技术方案的入口。

## 数仓分层

```text
ODS 原始数据层
  ↓
DWD 明细数据层
  ↓
DWS 汇总服务层
  ↓
ADS 应用数据层
  ↓
报表、接口、数据服务
```

## 建议补充内容

- 数据来源：业务库、日志、第三方接口、文件。
- 采集方式：离线同步、实时采集、增量抽取。
- 主题域：用户、订单、商品、设备、行为、财务等。
- 指标体系：原子指标、派生指标、复合指标。
- 调度体系：任务依赖、补数、失败重试、告警。
- 数据质量：空值、重复、波动、主外键一致性。
- 权限和安全：脱敏、分级、授权、审计。

## 关联章节

- Hadoop 生态。
- Hive 数据仓库。
- Spark 大数据引擎。
- Flink 实时计算。
- 服务器、运维和测试。

## 适用场景

- 同时接入业务库增量、每日全量数据和用户行为日志，并同时满足离线报表与实时查询。
- 需要将原始数据沉淀为 ODS、DIM、DWD、DWS、ADS 等分层数据资产，并为接口或可视化提供统一口径。
- 需要在采集、调度、计算、存储、数据质量、权限和可观测性之间形成可交付的项目闭环。

## 架构图解读

现有 [项目架构图](项目架构图.png) 已给出一条离线与实时并行的参考链路，阅读时可按数据来源、计算链路和消费出口三部分拆分：

- **业务数据链路**：Web/App 经过 Nginx 和 Spring Boot 服务写入业务 MySQL；图中每日全量数据通过 DataX 进入 Hadoop，增量数据由 Maxwell 进入 Kafka。
- **行为日志链路**：前端埋点数据经 Nginx、日志服务和日志文件，由 Flume 采集到 Kafka；Kafka 的业务与日志消费结果继续进入 Hadoop。
- **离线数仓链路**：Hadoop 中的数据按 ODS、DIM、DWD、DWS、ADS 分层加工；ADS 结果可经每日 DataX 同步到结果 MySQL，并由 Superset 进行离线可视化。
- **实时数仓链路**：Kafka 数据由 Flink 处理，图中以 ODS/DWD、Phoenix + HBase 维度数据、Redis 旁路缓存和 ClickHouse 宽表构成实时计算与查询链路；Spring Boot 数据接口服务向 Sugar 提供实时可视化数据。
- **协调与调度**：ZooKeeper 参与分布式协调，DolphinScheduler 负责任务调度；两者都需要和具体任务依赖、失败重试和告警策略一起维护。

## 项目实施路径

1. **盘点数据源**：列出业务 MySQL、日志、第三方文件或接口的负责人、主键、增量标识、更新频率、数据量、敏感级别和可回溯方式。
2. **设计数据模型**：按主题域确定 ODS、DIM、DWD、DWS、ADS 的粒度、主键、业务日期、分区、保留周期和下游消费者；离线层与实时层的指标口径必须可对齐。
3. **建设采集与调度**：分别配置 DataX、Maxwell、Flume、Kafka 等链路，明确全量、增量、补数和重复投递的处理方式；在 DolphinScheduler 中声明任务依赖、失败重试和告警。
4. **建设计算与存储**：离线处理依托 Hadoop/Hive/Spark 等章节的能力，实时处理依托 Flink；为维度查询、明细宽表和结果数据分别选择图中已有的 HBase/Phoenix、Redis、ClickHouse、MySQL 等存储。
5. **交付数据服务**：对 Superset、Sugar、Spring Boot 数据接口和其他消费者明确查询粒度、刷新频率、权限、限流与数据延迟说明。
6. **验证与运营**：对同一指标做源数据、离线结果和实时结果的核对；持续监控采集延迟、Kafka 积压、Flink 反压、任务失败、表分区、数据质量和可视化刷新结果。

## 常见产出

- 数据源台账、字段/事件字典、主键和增量规则，以及敏感数据分级清单。
- 主题域模型、分层表设计、维度与宽表设计、指标口径和血缘关系说明。
- DataX、Maxwell、Flume、Kafka、Flink、DolphinScheduler 等配置与部署/回滚说明。
- 离线与实时任务 DAG、补数策略、幂等策略、失败重试与人工处理流程。

- Superset/Sugar 看板、结果 MySQL 或数据接口的字段契约、刷新频率与权限说明。

## 维护建议

- 先约定业务日期、时区、主键、去重和迟到数据规则，再建设表和任务；这些规则应随数据模型和指标一起版本化。
- 全量同步、增量同步、实时消费和补数必须可区分、可重跑、可对账，避免不同链路写入同一结果后无法追溯。
- 任务、表、Topic、消费组、接口和看板都要标明负责人、上下游依赖与下线方式；新增字段和改口径前先做影响分析。
- 生产数据按最小权限、脱敏和审计原则使用；真实账号、连接串、Token 与原始敏感数据不写入文档、脚本示例或可视化截图。
- 后续可按本入口持续补充“数据源接入规范、分层建模规范、指标字典、调度与补数、数据质量、实时链路、数据服务”专题，但应以现有架构图和实际运行链路为准。
