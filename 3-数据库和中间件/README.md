# 数据库和中间件

## 章节定位

本章节覆盖后端系统常用的数据存储、缓存、搜索、消息、代理和 SQL 训练内容，是从单体应用走向高并发、高可用系统的关键基础。

## 适用场景

- 设计表结构、编写 SQL、处理字符集或主从相关问题时，需要快速定位数据库基础资料。
- 面对查询结果异常、慢查询、导入导出、监控告警等问题，需要按数据链路排查。
- 为业务选择 MongoDB、Elasticsearch、Kafka、Doris 或 Nginx 等组件时，需要先理解其适用边界。
- 准备数据库或数据开发面试时，需要以 SQL 题目和业务场景题做专项训练。

## 学习路径

1. 先掌握 SQL 基础、JOIN、聚合、窗口函数。
2. 学习 MySQL 表设计、索引、事务和锁。
3. 学习 MyBatis、MyBatis-Plus 等 Java 持久层工具。
4. 学习 MongoDB、Elasticsearch、Kafka 的适用场景。
5. 学习 Nginx 反向代理、负载均衡和静态资源配置。
6. 补充监控、备份、恢复、导入导出和故障排查能力。

## 从需求到排查的使用方式

```text
先确认数据模型和业务口径
  ↓
编写可验证的查询或操作
  ↓
检查 SQL 结果、索引和组件配置
  ↓
通过监控、日志和数据导出确认影响范围
  ↓
执行最小范围修复并复核结果
```

这套顺序适用于大多数数据问题：先确认“数据是否正确”，再确认“为什么慢或不稳定”，最后才考虑扩大到配置、架构或中间件层。

## 选型建议

- 强事务、复杂查询：优先关系型数据库。
- 文档结构灵活、字段变化频繁：可以考虑 MongoDB。
- 关键词搜索和日志检索：使用 Elasticsearch。
- 异步解耦、削峰、事件流：使用 Kafka。
- 实时报表和多维分析：可以考虑 Doris。
- 统一入口、反向代理、静态资源：使用 Nginx。

## 实战清单

- 写 SQL 前先明确主键、关联关系、统计粒度和时间边界；一对多关联后尤其要复核聚合结果。
- 表结构变更前检查默认值、空值、字符集、索引和已有数据兼容性。
- 更新或删除数据前，先用同条件的查询确认目标行；重要操作保留可回滚或可核对的依据。
- 使用消息、搜索或文档数据库前，先确认写入一致性、重复消费、数据同步和查询需求，避免只因“能用”就引入组件。
- 遇到性能问题时，区分数据库、应用连接、消息积压、搜索查询和代理层，不用单一指标替代完整链路判断。
- 导入导出、主从切换、配置变更等操作后，复核数据量、错误日志和关键业务查询。

## 维护原则

- SQL 题目、业务案例和生产操作指南分开维护，避免练习示例被误当作可直接执行的生产脚本。
- 文档中的连接地址、账号、密码、库表真实数据必须脱敏；示例使用占位符和最小数据集。
- 组件选型和参数结论应注明版本、部署方式与数据规模前提，不能直接迁移到不相同的环境。
- 涉及数据修复的记录应包含检查语句、变更语句和验证语句，便于复盘与审计。
