# 数据库监控指标

## 监控目标

数据库监控要回答四个问题：

1. 是否可用。
2. 是否变慢。
3. 是否存在资源瓶颈。
4. 是否有数据安全和容量风险。

## 核心指标

| 指标 | 含义 | 关注点 |
| --- | --- | --- |
| QPS | 每秒查询数 | 业务流量是否突增 |
| TPS | 每秒事务数 | 写入压力和事务提交压力 |
| 连接数 | 当前连接和最大连接 | 是否接近上限 |
| 慢查询 | 超过阈值的 SQL | 是否缺索引或 SQL 退化 |
| Buffer 命中率 | 内存缓存命中比例 | 是否频繁读磁盘 |
| IOPS | 每秒 IO 次数 | 磁盘是否成为瓶颈 |
| 主从延迟 | 从库落后主库时间 | 读写分离数据是否过期 |
| 锁等待 | 行锁、表锁、元数据锁 | 是否存在阻塞 |
| 磁盘空间 | 数据、binlog、归档日志 | 是否有写满风险 |

## MySQL 常用查看命令

### 连接数

```sql
SHOW STATUS LIKE 'Threads_connected';
SHOW VARIABLES LIKE 'max_connections';
```

### QPS 和 TPS

```sql
SHOW GLOBAL STATUS LIKE 'Questions';
SHOW GLOBAL STATUS LIKE 'Com_commit';
SHOW GLOBAL STATUS LIKE 'Com_rollback';
```

TPS 可以粗略按以下方式计算：

```text
TPS = Com_commit 每秒增量 + Com_rollback 每秒增量
```

### 慢查询

```sql
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'long_query_time';
SHOW GLOBAL STATUS LIKE 'Slow_queries';
```

开启慢查询：

```sql
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;
```

生产环境建议通过配置文件固定，避免重启后失效。

### InnoDB 状态

```sql
SHOW ENGINE INNODB STATUS\G
```

重点关注：

- `LATEST DETECTED DEADLOCK`：最近死锁。
- `TRANSACTIONS`：长事务和锁等待。
- `BUFFER POOL AND MEMORY`：Buffer Pool 使用情况。
- `ROW OPERATIONS`：行读写压力。

## 告警建议

| 场景 | 告警建议 |
| --- | --- |
| 实例不可连接 | 立即告警 |
| 磁盘使用率超过 80% | 告警并清理 binlog 或扩容 |
| 主从延迟超过 60 秒 | 告警并检查大事务、网络、从库压力 |
| 慢查询数量持续上升 | 告警并分析 SQL |
| 连接数超过上限 80% | 告警并检查连接池、慢 SQL |
| CPU 长时间超过 80% | 告警并分析 SQL 和实例规格 |

## 排查思路

### 查询变慢

1. 查看慢查询日志。
2. 使用 `EXPLAIN` 分析执行计划。
3. 检查是否命中索引。
4. 检查返回行数是否异常。
5. 检查是否存在锁等待。
6. 检查 CPU、IO、连接数是否达到瓶颈。

### 数据库连接打满

1. 查看当前连接数。
2. 查看连接来源 IP。
3. 查看是否有长时间 Sleep 连接。
4. 检查应用连接池最大连接数。
5. 检查慢查询或锁等待是否导致连接堆积。

```sql
SHOW PROCESSLIST;
```

### 磁盘空间不足

重点检查：

- 数据文件。
- binlog。
- 慢查询日志。
- 错误日志。
- 备份文件。

```bash
du -sh /var/lib/mysql/*
```
