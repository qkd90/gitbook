# Hadoop 生态：AI 与大数据招聘能力地图

Hadoop 生态是理解大规模离线数据“如何存、如何调度、如何靠近数据计算”的基础。即使新项目更多使用 Spark、Flink、湖仓或云服务，HDFS、YARN、MapReduce 的存储与执行模型仍是大数据开发、数据平台和 AI 数据工程岗位的重要面试底座。

> 本目录的学习目标不是停在单机安装成功，而是能够解释数据从采集落盘到被 Hive/Spark 消费的路径、角色、容量风险、失败恢复与权限边界。

## 一、岗位定位与招聘价值

| 目标岗位 | 面试中常见任务 | Hadoop 能力信号 | 与 AI 的连接 |
| --- | --- | --- | --- |
| 大数据开发 | 离线数据接入、清洗、批量计算、结果落盘 | HDFS、YARN、MapReduce、文件与目录治理 | 为训练、评估、特征生成提供稳定的历史数据底座 |
| 数据平台工程 | 集群资源、任务队列、存储目录、权限和容量管理 | 节点角色、资源调度、副本、故障处理 | 保障训练/批处理任务不因存储、资源或权限问题中断 |
| 数据仓库开发 | 原始数据入湖/入仓、分层和下游 SQL | HDFS 文件组织、分区输入、批次边界 | 管理标签、样本、特征等数据集的版本与保留周期 |
| AI 数据工程 | 数据集构建、批量预处理、数据质量与可复现 | 存储路径、输入输出契约、批次记录、权限 | 避免训练/评估使用未追溯、泄漏或错误版本的数据 |
| 后端 / 平台开发 | Java 客户端上传下载、任务提交与状态查询 | HDFS Java API、异常处理、权限和重试 | 将文件、离线结果或模型相关工件接入服务化流程 |

## 二、理解 Hadoop 的三层职责

```text
数据生产者 / 采集任务
          │
          ├─ HDFS：块、副本、目录、权限、NameNode / DataNode
          │
          ├─ YARN：资源申请、队列、ApplicationMaster、任务容器
          │
          └─ MapReduce / Spark / Hive：提交计算、靠近数据执行、输出结果
```

| 层级 | 解决的问题 | 招聘时应能说清的内容 |
| --- | --- | --- |
| HDFS | 大文件可靠分布式存储 | Block、副本、NameNode 元数据、DataNode 数据块、数据本地性、权限与目录规划 |
| YARN | 多任务共享集群资源 | ResourceManager、NodeManager、队列/资源、ApplicationMaster 和任务资源申请 |
| 计算框架 | 大规模批处理与结果落盘 | 输入切分、Map、Shuffle、Reduce、失败重试、输出目录和数据倾斜/小文件影响 |

先从 [Hadoop 简介](Hadoop简介.md) 和 [HDFS 核心概念](HDFS核心概念.md) 建立角色关系，再进入命令与编程实践。

## 三、HDFS：从“会上传文件”到“能管理数据资产”

### 1. 文件与目录设计

面试中应把路径设计说成数据契约，而不是随意的文件夹命名。一个离线数据路径至少需要体现：数据域、数据层级、表/主题、业务日期或批次、版本/来源，以及是否为临时产物。例如：

```text
/data/<domain>/<layer>/<dataset>/dt=YYYY-MM-DD/<version>/
/tmp/<job>/<run-id>/
/archive/<dataset>/<period>/
```

具体命名应跟随实际团队规范，但以下原则通用：正式输出与临时输出分离；可重跑批次不能覆盖未确认结果；清理策略明确；权限最小化；敏感数据不出现在目录名和测试样例里。

### 2. Block、副本和 NameNode 的业务影响

| 概念 | 需要理解的影响 | 典型排查问题 |
| --- | --- | --- |
| Block | 大文件被切分为多个块，影响并行度与数据分布 | 文件大小、块大小和任务切分是否合理？ |
| 副本 | 用于容错与读取可用性，也消耗存储和网络 | 副本不足、节点不可用或磁盘满时数据是否健康？ |
| NameNode | 保存文件系统元数据，是集群关键控制面 | 元数据、镜像/编辑日志、主备和恢复方案是否可用？ |
| DataNode | 存储数据块并汇报状态 | 节点磁盘、网络、心跳和块报告出现什么异常？ |
| 小文件 | 元数据和调度开销大，降低计算效率 | 为什么文件数量增长会拖慢 HDFS 和后续 Spark/Hive 作业？ |

不要把副本数、Block 大小或目录清理策略当成固定常量；需要结合存储容量、文件分布、任务模式和可靠性要求说明取舍。

### 3. 命令与 Java API 的招聘证据

[HDFS 常用命令](HDFS常用命令.md) 适合完成目录、上传、下载、查看、权限和统计的基础练习；[HDFS Java API](HDFS%20Java%20API.md) 应进一步练习：连接配置、资源关闭、异常处理、路径校验、临时文件/原子提交思路和错误日志。作品中避免硬编码真实集群地址和账号。

## 四、MapReduce 与 YARN：理解离线计算的成本

MapReduce 的关键不是把一个词频案例跑通，而是理解：输入如何切分，Map 输出为何需要 Shuffle，为什么网络传输、排序、聚合和数据倾斜会变慢，失败重试会如何影响运行时长和输出幂等。

| 阶段 | 面试官可能追问 | 推荐回答方向 |
| --- | --- | --- |
| InputSplit / Map | 为什么可并行？数据靠近计算有什么意义？ | 说明切分、数据本地性和输入文件布局的关系。 |
| Shuffle | 为什么通常昂贵？ | 涉及跨节点传输、排序、合并、磁盘 I/O；要观察键分布和中间数据量。 |
| Reduce | 为什么一个 key 热点会拖慢整体？ | 热 key/数据倾斜使某些 Reduce 负载过高，需要从 key 设计、预聚合或拆分策略处理。 |
| 输出 | 重跑会覆盖还是重复？ | 设计临时输出、成功标记、批次目录和原子切换/对账。 |
| YARN | 作业为何排队或被杀？ | 关注队列资源、容器内存/CPU、失败日志、并发与集群容量。 |

[MapReduce 编程模型](MapReduce编程模型.md) 是理解 Spark 等更高层计算引擎时的基线，不应只作为历史技术背诵。

## 五、与 AI 数据工程相连的实践要点

训练数据、标签、特征、评估数据和模型输出都需要可追溯的输入范围和版本。即使最终存储不使用 HDFS，下面的工程原则仍适用：

1. 数据集要记录来源、生成代码/作业版本、时间范围、过滤条件、schema 和质量统计。
2. 训练/评估集按实体或时间合理划分，避免未来信息泄漏或同一实体跨集合泄漏。
3. 原始数据、清洗数据、特征数据和模型输出分层保存，不让下游直接依赖未治理的临时文件。
4. 敏感数据按最小权限访问，样例、日志、截图和面试作品一律使用合成或脱敏数据。
5. 任务失败、补数或重跑后，必须用行数、去重数、时间范围、分区/文件清单或校验和等方式核对结果。

## 六、两个可实操作品 / 交付物

### 作品 A：离线数据入湖与批处理最小闭环

使用公开数据或自造的传感器/日志 CSV，搭建单机或伪分布式环境，完成：

- 将原始文件按日期批次写入 HDFS，记录目录、schema、行数和校验方式。
- 用 HDFS Shell 和 Java API 分别实现基础查看/上传/下载，处理不存在路径和重复上传。
- 编写一个 MapReduce 作业完成清洗或按日期/维度聚合。
- 输出到临时目录，检查成功后再切换到正式批次目录。
- 提供一次失败重跑说明：输入、输出、幂等策略和结果对账。

### 作品 B：面向模型训练的数据集版本说明

不需要训练真实模型。选择合成样本，设计“原始 → 清洗 → 特征/标签 → 训练/评估快照”的路径与元数据表，说明样本划分、时间边界、数据质量、权限、保留周期和回滚方式。它能证明你理解 AI 项目中“数据版本”与“模型版本”同样重要。

## 七、高频面试题与考察点

| 问题 | 建议回答要点 |
| --- | --- |
| HDFS 为什么适合大文件、不适合大量小文件？ | 大文件便于块级分布和吞吐；小文件增加 NameNode 元数据、任务调度和后续计算开销。 |
| NameNode 和 DataNode 分别做什么？ | NameNode 管理命名空间与块位置元数据，DataNode 存数据块并提供读写；还要说明高可用、容量和故障恢复的关注点。 |
| 副本机制带来哪些收益和成本？ | 容错和读取可用性提升，但占用存储并可能带来复制/网络开销；副本策略取决于可靠性与容量。 |
| MapReduce 的 Shuffle 为什么慢？ | 中间数据跨节点传输、排序、合并和磁盘 I/O 成本高；热点 key 和大量中间结果会加剧问题。 |
| 任务重跑如何避免产生重复数据？ | 批次 ID、临时目录、成功标记、原子发布、幂等写入和输入输出对账。 |
| YARN 中作业长期排队怎么排查？ | 检查队列资源/优先级、集群可用资源、并发、容器请求、失败重试和异常节点，不能只看应用代码。 |
| 如何保证训练数据可复现且不泄漏？ | 固化数据快照、来源、时间范围、过滤和划分规则；按实体/时间防止跨集和未来信息泄漏，并做质量校验。 |
