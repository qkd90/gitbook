# Java 开发

## 章节定位

Java 开发是整套技术体系的基础章节，主要覆盖语言基础、工程规范、算法训练、面试题和常用后端知识点。后续 Spring Boot、微服务、大数据组件的 Java API 都建立在这一部分之上。

## 适用场景

- 刚开始 Java 后端开发，需要补齐语言、HTTP 与编码规范基础。
- 在维护已有项目时，需要快速回顾命名、日期类型、包装类型等容易踩坑的细节。
- 准备面试或转岗，需要按专题完成剑指 Offer、LeetCode 与动态规划训练。
- 阅读 Spring、微服务或大数据代码前，需要先建立集合、异常处理、面向对象和算法复杂度的共同语言。

## 学习建议

先把 Java 基础和代码规范看完，再进入算法题目录。算法题不要只看答案，建议按“题目理解、暴力解法、优化思路、复杂度分析、代码实现、复盘总结”的顺序整理。

## 按目标学习

### 面向日常开发

1. 阅读 Java 基础、包装类型、日期类型与 HTTP 文档，建立常用概念的判断标准。
2. 结合代码规范和 Java 开发规范，检查自己项目中的命名、异常处理和接口职责。
3. 再进入 [开发框架和工具](../2-开发框架和工具/README.md)，将语言能力落实到工程配置、日志和接口治理中。

### 面向算法与面试

1. 从数组、字符串、链表、栈队列等基础题型开始，先写出可运行的解法。
2. 再学习二叉树、回溯、动态规划、图等需要模板和状态设计的题型。
3. 每题保留输入输出边界、时间复杂度和空间复杂度；隔一段时间独立重做，而不是只复读答案。

## 实战自检清单

- 新增接口前，能说明请求方法、资源语义和异常返回的处理方式。
- 处理金额、计数、日期和空值前，确认类型选择与边界条件。
- 提交代码前，能用规范文档检查命名、可读性和重复逻辑。
- 算法题完成后，能给出复杂度，并覆盖空集合、单元素、重复值和边界下标。
- 遇到框架问题时，先回到 Java 语言层确认对象生命周期、集合行为和异常链路。

## 维护原则

- 新增学习笔记时优先放入对应专题，标题写清问题或场景，避免形成无法检索的零散记录。
- 题解应保留思路和复杂度，代码仅作为思路的验证，不将只可运行但无解释的片段当作总结。
- 对版本、JDK 或第三方库强相关的结论，标注适用条件；基础语言结论与项目约定分开记录。
