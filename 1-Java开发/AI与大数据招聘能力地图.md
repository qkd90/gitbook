# Java 开发：AI 与大数据招聘能力地图

## 使用范围

本页面向 AI 应用后端、大数据研发和后端平台岗位的准备，作用是把本目录已有的语言基础、编码规范、HTTP 与算法资料转成可以证明的能力。

它不是 Java 全量学习清单，也不把“看过题目”当成“能在项目中交付”。每一层都应留出代码、测试、设计说明或排查记录作为证据。

## 岗位关联

### AI 应用后端

- 模型、检索或工作流服务最终需要稳定的 HTTP 接口、清晰的请求对象和可追踪的异常返回；本目录的 HTTP、CRUD 与代码规范资料是这层接口能力的基础。
- AI 请求常有长耗时、重试、并发和结果状态等问题。Java 基础中的线程安全内容可用于建立并发边界意识，但线程池、超时和异步编排仍需在后续补齐。
- 面试中不要只说“接过大模型接口”。应能解释输入如何校验、结果如何落库或追踪、失败如何向调用方表达，以及什么数据不能写进日志。

### 大数据研发

- Hadoop、Spark、Flink 等生态常以 Java API 或 JVM 运行时作为入口。当前 README 已把 Java 基础列为阅读这些组件代码前的共同语言。
- SQL、任务调度和流批处理之外，面试官仍会考察集合、对象模型、序列化意识、异常处理和算法复杂度；本目录的基础与算法题正好用于补这一层。
- 大数据岗位中的 Java 题不应只做输入输出题，还应能说明海量数据下对象创建、重复扫描、排序、哈希冲突和内存压力的取舍。

### 后端平台与业务中台

- 平台岗位通常看重接口边界、领域命名、编码一致性、可维护性和故障可定位性，这些都能从 Java 开发规范、代码规范和 CRUD 语义中形成统一表达。
- 算法训练的价值不在背模板，而在于面对缓存、去重、分页、聚合、树形结构与状态机时能先识别数据结构和复杂度。
- 若目标岗位更偏工程交付，应把本目录与开发框架和工具、数据库和中间件、微服务目录连起来准备，而不是单独展示语言题。

## 能力分层与可验证证据

| 层级 | 招聘中真正要回答的问题 | 本目录可建立的能力 | 建议留下的证据 |
| --- | --- | --- | --- |
| L1 语言正确性 | 类型、空值、日期和对象语义是否会造成线上错误 | 基础类型、包装类型、日期类型、对象与集合的基本判断 | 小型示例、边界输入和断言结果 |
| L2 代码可维护性 | 别人是否能读懂并安全修改代码 | Service、DAO、领域模型、CRUD 等命名约定 | 重构前后对比、命名说明、代码审查清单 |
| L3 接口语义 | HTTP 方法、参数和错误应该怎样表达 | HTTP 请求类型、资源操作和返回边界 | 接口契约、请求样例、失败样例 |
| L4 并发与资源意识 | 多个请求同时到来时数据会不会错、任务会不会失控 | 线程实现、线程安全和工作区的基础认识 | 并发测试记录、共享状态说明、退出条件 |
| L5 算法与复杂度 | 方案在数据量放大后是否仍可接受 | 数组、链表、树、栈队列、回溯、动态规划、图 | 题解、复杂度、边界用例和复盘 |
| L6 工程连接能力 | 语言能力如何落到服务、数据和平台 | 将 Java 基础接到 Spring、SQL、微服务与大数据 API | 小项目 README、模块图、运行与验证命令 |

L1 到 L3 是 AI 应用后端和业务后端的最低可用基础；大数据研发还需把 L4、L5 转成对数据规模和资源成本的解释；平台岗位则更看重 L2、L3、L6 的持续性。

## 可实操项目与交付物

### 项目一：可审计的 AI 任务提交接口

项目目标是用 Java 完成一个不依赖具体模型厂商的任务提交和查询接口，用来证明接口设计、状态表达和异常边界，而不是声称已经完成模型训练。

- 设计提交、查询、取消三个操作，明确每个操作对应的请求方法、输入字段、返回字段和不可变字段。
- 对任务名称、调用参数、调用方标识、提交时间和状态设计明确类型；日期和空值处理要能够追溯到本目录的类型资料。
- 把任务状态设计为有限集合，至少覆盖待处理、处理中、成功、失败、取消；不要用含义不明的整数散落在业务代码中。
- 为重复提交、空参数、非法状态流转、未知任务、内部异常分别给出可区分的返回样例。
- 记录并发提交时的共享数据策略：如果只是内存演示，要明确其不适合多实例；如果没有做并发控制，也应在 README 中如实说明限制。

建议交付物：

- 一份接口契约，包含正常、参数错误和状态冲突的请求响应示例。
- 一份状态流转图和字段字典，说明哪些字段由调用方传入、哪些由服务生成。
- 一组覆盖空值、重复、边界时间和并发提交的测试用例。
- 一份问题复盘，说明一次类型、日期或异常设计失误如何被测试发现。

### 项目二：数据处理规则与查询性能练习

项目目标是把算法题的复杂度意识放进业务处理。可以使用模拟订单、事件或传感器数据，不使用真实用户或医疗数据。

- 选择一个需要去重、排序、滑动窗口统计或树形聚合的规则，例如按用户与时间窗口去重事件。
- 先写出直接遍历的版本，再基于哈希表、双指针、堆或动态规划思路给出优化版本。
- 对每个版本标注时间复杂度、空间复杂度和数据量增大时的风险，而不只展示最终代码。
- 设计重复事件、乱序时间、空集合、单元素、极大输入和边界下标等测试数据。
- 若结果需要通过 HTTP 暴露，复用项目一的接口契约方式，避免把算法逻辑直接塞进控制器。

建议交付物：

- 规则说明、输入输出样例和复杂度对比表。
- 两种实现的基准数据，记录数据规模、执行时间和机器环境，不编造性能数字。
- 失败用例与修复说明，特别是重复、溢出、空值和时间边界。
- 一页“为什么不选择另一种算法”的取舍记录。

### 项目三：算法题到工程问题的映射册

这是一份适合校招、转岗或缺少完整项目时使用的补充作品，而不是刷题截图合集。

- 从本目录的数组、链表、树、LRU、图、回溯和动态规划题中至少选择六类。
- 每类挑一题写成“原题抽象 → 工程场景 → 复杂度 → 边界 → 代码”的结构。
- 例如 LRU 可映射到缓存淘汰，课程表/图可映射到任务依赖，岛屿数量可映射到连通区域识别；映射只说明思考方式，不宣称它就是生产实现。
- 对每题列出何时不能直接套模板，例如并发缓存需要额外同步、真实任务依赖需要持久化和失败恢复。

## 交付质量自检

- 每个项目是否能在不依赖口头解释的情况下说明目标、输入、输出、状态和限制。
- 每个关键方法是否有对空值、重复、时间边界、异常和取消的处理说明。
- 接口是否把业务失败与系统失败分开，避免调用方无法判断是否该重试。
- 算法是否至少给出复杂度和数据规模假设，避免把小样本结果误用于大数据量。
- 并发演示是否明确共享对象、锁/队列边界、停止条件和未覆盖的多实例场景。
- 文档中的配置、账号、地址和业务数据是否均为占位符或脱敏内容。

每次复盘至少补一条“当初的错误假设是什么、怎样用测试或日志推翻、最终怎样缩小修复范围”。这比新增一段没有验证的示例代码更能体现工程判断。

面试作品应保留可运行版本、题解版本和复盘版本，避免事后修改后无法解释最初方案的不足。

## 简历与面试表达

### 简历写法

不要写“熟悉 Java、熟悉算法、熟悉 AI”。更可信的结构是“问题—方法—验证—边界”。

- 接口类：实现任务提交与状态查询接口，明确参数校验、状态流转和异常返回；使用实际字段数、测试用例数或完成范围替换占位描述。
- 规则类：针对去重或窗口统计问题比较直接遍历和哈希优化方案，给出复杂度和边界用例，不虚构吞吐或节省比例。
- 规范类：按 Java 命名与 CRUD 语义梳理接口/服务职责，形成代码审查清单并用于实际改动。
- 算法类：完成若干类别题目的独立复盘，能够解释状态、复杂度和工程化限制，而不是仅写“刷了 X 题”。

### 面试考察点

1. 为什么基本类型之外还需要包装类型？空值、集合泛型和序列化场景分别怎样影响选择？
2. 为什么现代 Java 代码应谨慎处理旧日期类型？业务日界、格式化、时区和空值如何测试？
3. POST、PUT、PATCH、DELETE 分别适合什么语义？重复请求时如何定义行为？
4. 一个 Service 方法在多线程访问下为什么可能不安全？共享状态、可变集合和退出条件怎么分析？
5. 如何从暴力解法推导哈希、双指针或动态规划优化？怎样证明复杂度？
6. LRU 缓存为什么通常需要哈希表和双向链表？如果进入并发服务还要补什么？
7. 二叉树序列化、任务依赖图或窗口去重在真实服务中有哪些数据一致性和持久化限制？
8. 让你设计一个 AI 调用结果接口，参数错误、调用超时、任务失败、重复提交各怎样返回？

回答时先给判断标准，再给方案和边界。例如先说“幂等性取决于业务资源和请求标识”，再说明如何验证，不要直接背注解或框架名称。

## AI 协作方法

AI 可以加速样例、测试和审查，但 Java 的语义、运行结果和复杂度必须由开发者负责。

1. 先把需求写成可验证的问题：输入、输出、不变量、错误场景、数据规模和是否允许重复。
2. 让 AI 分别给出直接解和优化解，并要求列出复杂度、隐藏前提和反例。
3. 用本目录的规范检查生成代码：命名是否表达 Service/DAO/领域含义，是否混淆 CRUD 语义，是否把复杂逻辑堆到接口层。
4. 请 AI 生成边界测试清单，再由自己补充项目特有的时间、空值、重复和并发场景。
5. 用编译、单元测试、接口测试和人工代码审查验证；模型生成的解释不能替代运行证据。
6. 不向 AI 提供生产密钥、真实用户数据、内部地址或未脱敏日志；示例使用虚构或脱敏字段。
