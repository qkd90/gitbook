# Go 开发

## 章节定位

Go 开发章节用于沉淀 Go 语言基础、并发模型、Web 服务和微服务工程实践，目标是形成从“写出一个可运行程序”到“交付一个可维护服务”的学习路径。

当前目录暂未收录独立主题文章，以下内容用于明确后续补充方向和阅读顺序。跨项目的 Go 研发约束可参阅 [Go 项目指令](../5-Python和AI/go项目.md)。

## 招聘准备入口

- [AI 与大数据招聘能力地图](./AI与大数据招聘能力地图.md)：在资料尚少的前提下，明确 Go 面向 AI 服务、数据接入和平台后端的可实操项目、面试考察点与 P0 补齐顺序。

## 适用场景

- Java 后端开发者学习 Go 的类型、接口、错误处理和包管理差异。
- 编写带超时、取消和并发控制的 API 或后台任务。
- 建立 Go Web 服务的配置、日志、数据库访问、测试和容器化交付流程。
- 对既有 Go 微服务进行接口定位、故障排查和小范围功能迭代。

## 学习与实践路径

1. **先建立语言心智模型**：掌握值与指针、结构体、隐式接口、slice/map，以及显式返回 `error` 的写法，不照搬 Java 的异常和继承思维。
2. **再理解请求生命周期**：从 `context` 的超时、取消和调用链传递开始，结合 `goroutine`、`channel` 和 `sync` 区分通信、同步与资源保护。
3. **完成一个最小 Web 服务**：使用 `net/http` 或现有项目采用的 Web 框架，实现路由、参数校验、错误返回和日志。
4. **按工程方式完善服务**：补齐配置读取、数据库访问、接口测试、超时处理和部署说明。
5. **最后进入微服务实践**：在真实项目中沿用既有 Controller/Logic/DTO/VO、RPC、事件和日志模式，先追踪调用链再改动。

## 重点提醒

- Go 接口由方法集隐式实现，设计时优先围绕行为而不是类层级。
- `goroutine` 不等于线程；并发前应先明确数据所有权、退出条件和错误处理。
- `context` 用于请求范围的超时和取消，不应用 `context.Background()` 任意切断调用链。
- 新增服务代码应复用目标项目的分层、日志、错误和 RPC 约定，避免为了“通用化”引入新的架构。
