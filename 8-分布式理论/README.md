# 分布式理论

分布式系统是现代大数据架构的核心。本章节涵盖分布式系统的基础理论，包括 CAP 定理、一致性协议、分布式锁与事务等核心概念。

## 学习路径

```
分布式系统基本概念 → CAP理论 → Paxos算法 → Raft算法
                                    ↓
                    分布式锁解决方案 ← 分布式事务解决方案 ← 分布式ID生成方案
```

## 适用场景

- 服务从单实例扩展到多实例后，需要处理网络抖动、节点故障、数据副本和请求重复。
- 多个服务共同修改同一业务状态，需要选择一致性、锁、幂等、事务或补偿策略。
- 订单、支付、库存、任务调度等场景需要在性能、可用性、复杂度和数据正确性之间做可解释的取舍。

## 知识地图

- **问题起点**：[分布式系统基本概念](分布式系统基本概念.md) 说明节点、网络和时间都不再可靠，是后续设计约束的来源。
- **一致性取舍**：[CAP理论](CAP理论.md) 帮助明确分区发生时优先保证什么；[Paxos算法](Paxos算法.md) 与 [Raft算法](Raft算法.md) 解释多数派共识的基础。
- **并发协调**：[分布式锁解决方案](分布式锁解决方案.md) 聚焦互斥访问、锁粒度、超时与释放问题。
- **跨服务一致性**：[分布式事务解决方案](分布式事务解决方案.md) 覆盖 2PC、3PC、TCC、SAGA 等模式，适合按业务可逆性和一致性要求选择。
- **全局标识**：[分布式ID生成方案](分布式ID生成方案.md) 用于分析 UUID、号段和雪花算法在唯一性、有序性与依赖关系上的差异。

## 学习与实践路径

1. 先用一个多实例服务的例子画出请求、存储、缓存和消息的边界，再列出可能出现的超时、重复、乱序和节点故障。
2. 阅读 CAP 和共识算法时，重点记录“发生网络分区时系统如何取舍”，不要只记定义。
3. 为一个共享资源设计锁方案，明确锁对象、持有者、超时、续期、失败处理和重复请求的行为。
4. 为一个跨服务流程比较事务、最终一致性和补偿方案，写清成功路径、失败路径、重试和人工介入边界。
5. 将最终结论沉淀为可评审的时序图、状态机和接口幂等约定，再进入编码实现。

## 常见产出

- 分布式场景的时序图、状态流转图和架构决策记录。
- 锁的键设计、有效期、重试策略和异常释放方案。
- 跨服务交易的幂等键、补偿动作、对账口径和故障恢复预案。
- 全局 ID 的选型说明、容量估算、时钟或号段依赖说明。

## 维护建议

- 不要把“分布式”当作自动获得高可用；每项方案都应写明故障假设和降级后的业务结果。
- 锁与事务策略变更前，先评估重复执行、超时、消息延迟和人工补偿的影响，不只验证正常路径。
- 技术方案应附带监控点，例如锁等待、失败率、重试量、事务补偿量和 ID 生成异常，便于上线后验证假设。
- 需要具体协调能力时，可结合 ZooKeeper 等实际组件章节继续验证；理论文档应随着真实事故和复盘持续补充边界条件。
