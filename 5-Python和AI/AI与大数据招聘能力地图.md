# AI 与大数据招聘能力地图

> 本页只根据本目录现有的 Python、FastAPI、Hugging Face、DeepSeek-R1、CGMformer 和 AI 协作资料整理。它说明的是可被招聘方追问、验证的能力边界，不把“看过文档”包装成“已经完成大规模训练或生产上线”。

## 一、适合投递的岗位与当前定位

本目录是整个知识库中与 **AI 应用工程、模型工程和数据处理** 最直接相关的一部分。它不是单纯的“会调用大模型”，而是覆盖了环境、数据、模型、服务和研发协作五个层面。

| 岗位方向 | 与现有资料的对应关系 | 当前可主张的能力 | 投递前还应补强的证据 |
| --- | --- | --- | --- |
| AI 应用工程师 / LLM 应用工程师 | DeepSeek-R1 + Ollama、FastAPI、AI 工具实践、项目级规则 | 本地模型服务部署思路、接口化交付、提示词和 AI 协作边界 | 一个可运行的检索/工具调用应用、鉴权与观测、质量评估结果 |
| Python AI 工程师 | Conda、PyCharm、PyTorch 安装、Hugging Face、FastAPI | 独立环境管理、Python 服务启动、Dataset 预处理阅读 | 可复现仓库、单元测试、依赖锁定、部署脚本 |
| 模型工程师 / 算法工程师（偏工程落地） | CGMformer、模型代码总结、随机种子、分类/回归推理 | 数据处理—预训练—嵌入—分类/回归推理链路的理解 | 数据切分、指标、模型版本、实验对比和真实推理验证 |
| 医疗健康 AI 应用工程师 | CGMformer 与近期项目复盘 | 理解健康数据需要脱敏、模型输入契约和非诊断边界 | 合规方案、脱敏样本、医生/业务审核和线上监控 |
| 数据工程师（Python 辅助方向） | pandas、Dataset、数据处理脚本、FastAPI 服务化 | 小规模数据处理与模型特征输入的衔接 | SQL、数仓分层、调度、流计算和数据质量项目证据 |

**诚实定位：**目前最适合突出的是“懂模型输入输出、能把 Python/模型能力服务化、并会用 AI 提升研发效率”的工程型候选人，而不是仅凭本目录就宣称完成过大规模预训练、SOTA 调参或成熟 MLOps 平台建设。

## 四、可交付的实战项目：把资料转成作品集

### 项目一：脱敏时序数据的模型推理 API

**目标：**以 CGMformer 的数据准备和分类/回归推理资料为参照，做一个不使用真实个人数据的最小推理服务。

```text
脱敏 CSV / JSON
  → schema 与时间窗口校验
  → 预处理（特征顺序、缺失值、归一化）
  → 加载固定版本模型/权重
  → FastAPI 推理接口
  → 结构化结果、模型版本、请求日志和错误码
```

**应交付：**

- `/health`、`/v1/predict` 等接口契约，明确字段、单位、时间序列长度、空值策略和错误码。
- 可复现环境文件、脱敏样例、模型/权重来源说明与启动命令；权重和真实数据不提交到公开仓库。
- 预处理单元测试：少一条采样、乱序、重复时间戳、空值、特征列错序均应有明确行为。
- 至少一份结果验证记录：确认请求能跑通不等于模型效果已验证，必须分开记录“接口正确性”和“模型评估指标”。

**验收口径：**从一个全新环境按文档启动；同一版本输入得到可解释的稳定输出；请求日志能关联模型版本和数据 schema；错误输入不会悄悄被模型“猜测”成正常结果。

### 项目二：本地大模型知识助手的工程化最小闭环

**目标：**基于 DeepSeek-R1/Ollama 部署资料，做一个面向内部 Markdown 文档的问答或研发助手。该项目侧重 AI 应用工程，不声称在训练基础模型。

**应交付：**

- 文档采集范围、脱敏规则、切分/索引策略和资料更新时间；对无法回答的问题返回“不确定/无依据”。
- FastAPI 或同类服务接口、会话/请求限额、超时与失败降级；模型不可用时不能阻塞整个业务流程。
- 一组可复跑的评估问题，记录“有依据回答、拒答、引用错误、延迟”四类结果。
- 使用场景限定为文档导航、代码解释、需求澄清和测试用例草案；不将医疗、财务或生产写操作交给模型自动决策。

### 项目三：AI 辅助研发质量门禁样例

**目标：**把本目录已有的 Go/Java 项目规则和 AI 协作总结转成团队可复用的工作流。

**应交付：**

- 一份任务提示词模板：目标、真实代码路径、输入输出契约、不可动范围、验证命令和风险项缺一不可。
- 一份 AI 变更审查清单：协议兼容、空值、时间边界、权限、日志、测试覆盖与回滚。
- 至少一个“AI 出草案—人工核对真实调用链—最小改动—运行验证”的脱敏案例复盘。

目录中的 `glucose-wave` 分工描述可用作协作案例：AI 可以承担前端界面与样板代码生成，但后端接口、健康数据语义、鉴权和验收仍由人工负责。该分工来自既有复盘说明，若面试使用，应如实说明是否已阅读并验证对应项目源码。

## 六、面试高频追问与回答要点

1. **为什么模型工程不等于“调用一次 `predict`”？**
   - 回答应覆盖数据 schema、特征顺序、时间窗口、归一化、标签映射、权重版本、设备、依赖、异常输入和结果解释；任一项不一致都可能让接口可用但结果失真。
2. **如何做实验可复现？**
   - 固定随机种子只是起点；还要记录数据版本和患者/实体切分、代码 commit、依赖、配置、权重、硬件与评估脚本，避免未来信息泄漏。
3. **FastAPI 服务上线前最小检查是什么？**
   - 请求校验、健康检查、超时、结构化日志、错误码、并发/资源上限、模型加载生命周期、测试样例与部署回滚。
4. **文本 Tokenization 或音频重采样为什么属于工程风险？**
   - 它们决定输入分布和 shape；训练与推理使用不同规则时，模型输出没有可比性。
5. **模型输出可以直接当医疗结论吗？**
   - 不可以。健康场景要脱敏、明确适用范围和不确定性，产品展示与临床/业务审核必须分层，模型输出不能替代诊断。
6. **本地模型和云端模型如何选择？**
   - 比较数据边界、延迟、成本、模型能力、运维负担和离线可用性；不是单纯比较模型名称。
7. **AI 生成的代码如何验收？**
   - 先阅读真实调用链和相邻实现，再核对接口、数据库/消息语义、空值和时间边界；最后用格式检查、编译、单测或最小运行验证确认。
8. **为什么需要提示词和项目规则？**
   - 它们把隐含团队约定显式化，但不能替代代码审查。规则应限制数据、改动范围、验证要求和异常处理。

## 七、AI 协作方式：让 AI 加速，而不是替你背书

适合交给 AI 的工作包括：梳理目录和调用链、把接口/字段整理成表、生成测试边界清单、起草 FastAPI 骨架、解释报错、将复盘整理为文档。必须由人确认的工作包括：真实数据口径、医学/业务结论、模型效果、权限、上线开关、数据库和生产写操作。

一个适用于本方向的提示词骨架：

```text
你负责协助一个 Python 模型服务任务。
已知资料：<真实目录与入口文件>。
目标：<接口/预处理/文档的具体目标>。
输入契约：<字段、单位、shape、时间排序、缺失值规则>。
输出契约：<字段、模型版本、错误码、不能推断的内容>。
限制：不读取真实医疗数据；不修改权重、依赖或接口路径；不要把猜测写成事实。
请先列出调用链、风险和验证项，再给出最小修改方案。
验证：<py_compile、单测、匿名样例、启动检查等>。
```

这类提示词的价值在于让 AI 在动手前暴露不确定点。尤其是 `glucose-wave` 这类 AI 参与前端生成的项目，接口契约必须先由后端和业务确定，再让模型生成页面；不能反过来根据生成页面猜测业务字段。

## 九、投递前自查清单

- 能在 5 分钟内演示一个从安装环境到调用接口的最小闭环。
- 能展示一个脱敏输入样例，并解释每个字段如何进入预处理和模型。
- 能说明一个失败样例：依赖不匹配、字段错序、模型文件缺失或超时如何被发现和处理。
- 能区分“资料理解”“代码已实现”“离线验证完成”“真实环境上线”四种状态。
- 能说清 AI 在项目中的职责、人工复核点和不可自动化的风险边界。

做到这些，本目录就能从零散的工具说明，转化为面向 AI 应用、模型工程和数据处理岗位的可信作品集骨架。
