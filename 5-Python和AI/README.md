# Python 和 AI

## 章节定位

本章节记录 Python 环境管理、FastAPI 服务部署、Hugging Face、DeepSeek、CGMformer，以及 AI 辅助研发的实践。它连接了两类能力：一类是把 Python/模型代码跑起来并稳定交付；另一类是把提示词、项目指令和复核流程沉淀为可复用的研发方法。

适合以下场景：

- 第一次搭建 Python 或 Conda 项目环境。
- 将 Python 脚本或模型能力封装为 FastAPI 服务。
- 阅读 Hugging Face 数据处理、模型代码或 CGMformer 相关资料。
- 在本地部署 DeepSeek-R1，或建立 AI 辅助编码的协作规范。

## 推荐学习与实践路径

### 路径一：Python 服务入门

1. 先完成 Conda/Miniconda 安装，创建独立项目环境。
2. 在 PyCharm 中绑定该环境，确认终端与 IDE 使用同一解释器。
3. 按 FastAPI 文档启动最小服务，再补充依赖、日志和部署配置。
4. 最终留下环境名称、Python 版本、依赖清单、启动命令和健康检查方式。

### 路径二：模型代码与推理

1. 从 Hugging Face 数据集与预处理方式开始，先弄清输入数据的来源和形态。
2. 阅读模型代码总结，关注随机种子和可复现实验的前提。
3. 再进入 CGMformer，分别核对数据目录、处理脚本、预训练和分类/回归推理链路。
4. 每次实验都记录数据版本、依赖版本、模型/权重来源、输入输出格式与结果口径；模型权重和大数据不提交到代码仓库。

### 路径三：本地模型与 AI 辅助研发

1. 先根据 DeepSeek-R1 文档完成本地模型服务的安装、启动和日志查看。
2. 阅读研发实践总结，选择“代码理解、实现、排查、文档整理”中的一个小场景试用。
3. 提示词中提供任务目标、真实代码路径、输入输出约束、不可修改范围和验证要求。
4. 将稳定有效的项目规则放入对应项目指令，代码、数据库变更和健康相关结论仍由人工复核。

## 交付与维护建议

- 一个可运行的 Python 项目至少应说明：解释器/环境名称、依赖来源、启动命令、配置位置、输入输出示例和停止方式。
- 环境、数据、模型和服务应分别记录版本与来源；遇到问题时先核对解释器、依赖、模型文件、端口和资源占用。
- 模型权重、真实业务数据、Token、连接串等不放入 GitBook 示例或代码仓库。
- AI 生成的内容应经过接口契约、字段含义、边界条件、测试结果和安全性复核；它可以加速实现，不替代业务责任。

## 后续维护方向

- 新增资料时优先补齐“适用版本、前置条件、输入输出、验证命令、常见失败现象”。
- 模型和服务文档应明确数据格式、设备/显存要求、权重路径和失败时的降级方式。
- 已经验证有效的提示词、项目规则和排查模板可持续沉淀，但不写入敏感配置或真实用户数据。
