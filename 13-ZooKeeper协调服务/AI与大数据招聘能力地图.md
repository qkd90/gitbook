# AI 与大数据招聘能力地图

> 本页基于本目录已有的 ZooKeeper 概念、单机/集群部署、Shell 操作和 Java/Curator 客户端资料整理。ZooKeeper 不是 AI 模型训练的核心技能，但它能证明候选人理解分布式协调、服务可用性和平台运行边界；这些能力对实时计算、数据平台和 AI 基础设施岗位有辅助价值。

## 一、岗位定位：把协调能力放在正确的位置

| 岗位方向 | ZooKeeper 的相关性 | 本目录可准备的能力点 | 应诚实说明的边界 |
| --- | --- | --- | --- |
| 数据平台 / 大数据运维工程师 | 高 | 集群、节点元数据、会话、ACL、故障感知、排障 | 不应仅凭本目录声称维护过大规模生产集群 |
| 实时计算工程师 | 中高 | 理解流处理/消息系统可能依赖的协调服务、发布与故障影响 | Flink 作业开发的核心仍是时间、状态、数据契约与计算逻辑 |
| Java 分布式应用工程师 | 高 | 原生客户端、Curator、Watcher、分布式锁、Leader 选举 | 锁并不是解决所有并发问题的默认方案 |
| AI 平台 / MLOps 工程师 | 中低 | 了解配置、服务发现、任务主从切换等基础设施概念 | 不能把 ZooKeeper 说成模型训练、RAG 或 Agent 的必备核心能力 |

招聘表达的重点应是：**我知道协调用于保存少量元数据和协调状态，不用它承载高频业务数据，也不会把“有分布式锁”误当成系统一定正确。**

## 四、可交付实战项目

### 项目一：可恢复的任务 Leader 选举服务

**场景：**多个 Java 实例中只有一个可以执行“定时聚合/数据回补”任务，其他实例待命。使用 Curator 的 `LeaderSelector` 和临时节点实现主从切换演练。

```text
应用实例 A / B / C
  → Curator 连接与重试
  → /demo/leader 下选主
  → 当前 Leader 执行受控任务
  → 连接中断/进程退出
  → 临时节点消失、重新选主
  → 日志与任务执行记录对账
```

**应交付：**

- ZNode 路径规范、节点类型、ACL 策略和数据格式说明。
- `LeaderSelector` 生命周期代码：启动、取得主节点、退出主节点、关闭客户端的处理方式。
- 三实例演练脚本或步骤：启动顺序、当前 Leader、主动停止 Leader、接替结果、恢复原实例。
- 任务幂等说明：Leader 切换时如何避免同一业务批次被重复执行或无记录丢失。
- 指标/日志字段：实例 ID、会话状态、选主事件、任务批次、成功/失败和切换耗时。

**验收点：**停止当前 Leader 后能出现新的 Leader；原 Leader 不能在失去领导权后继续写结果；重复启动、网络抖动和重连不会把“选主成功”误当作“任务必然只执行一次”。

### 项目二：配置中心监听与灰度配置演练

**场景：**在 `/demo/config` 保存一个小型、非敏感的 JSON/文本配置，由两个客户端监听变化并更新本地只读缓存。这个项目用于理解 Watcher、Cache 和配置版本，不用于存储大配置或真实秘钥。

**应交付：**

- 配置 schema：版本号、开关、更新时间、发布人；明确不能放密码、Token 和用户数据。
- 使用 `NodeCache` 或 `PathChildrenCache` 的监听代码，包含首次加载、空数据、节点删除、重连和关闭逻辑。
- 发布—通知—客户端生效的时序图；说明 Watcher 的触发与重新注册/客户端库封装关系。
- 一个回滚操作：把配置版本恢复到上一个安全值，并记录哪台客户端收到何种事件。
- 人工验证表：两个客户端均显示正确版本、变更失败不会加载半截配置、日志不回显敏感值。

### 项目三：分布式锁的边界测试

**场景：**用 `InterProcessMutex` 模拟两个实例竞争一个小的临界区，例如“生成某日汇总文件”。重点是测试锁的获取、释放、超时与异常路径，而不是把锁用于高频业务主链路。

**应交付：**

- 锁路径、竞争粒度、最长持有时间和失败策略说明。
- `try/finally` 释放锁的代码与异常测试；明确连接失效后的业务恢复逻辑。
- 压力/并发下的执行记录，证明同一批次被保护的临界区没有并行进入。
- “不使用锁”的替代评估：数据库唯一约束、幂等键、队列顺序或单实例任务是否更简单可靠。

## 五、简历表达：可被验证的版本

| 能力点 | 可使用的表述（完成后） | 面试官可能追问 |
| --- | --- | --- |
| 协调建模 | “设计 ZNode 层级、节点生命周期和 ACL 边界，用于配置/任务协调等少量元数据管理。” | 为什么节点要小？临时节点何时消失？ |
| Java 客户端 | “使用 Curator 完成连接重试、节点监听和客户端关闭，处理节点变更与重连场景。” | Watch 丢失/会话过期时怎么做？ |
| Leader 选举 | “基于临时顺序节点或 Curator LeaderSelector 演练主从切换，并为任务设计幂等记录。” | 选主成功能否保证任务只执行一次？ |
| 分布式锁 | “在明确粒度和超时边界下使用 InterProcessMutex，并通过 finally 释放和异常场景验证。” | 锁丢失、死锁、长临界区怎么办？ |
| 平台运维 | “记录集群节点、数据目录、日志、会话和安全检查项，形成测试环境排障手册。” | 多数派、磁盘、连接数如何影响可用性？ |

不要把“看过 Curator 示例”写成“建设过高可用服务注册中心”。如果没有实际集群、客户端和切换演练证据，应写“完成学习/实验”，而不是生产成果。

## 六、面试高频问题与考察点

1. **持久节点、临时节点、顺序节点各适用于什么？**
   - 要结合生命周期回答：配置可用持久节点；实例存活可用临时节点；排队/选主可用顺序节点；不能只背定义。
2. **Watcher 为什么不能被当作永久订阅？**
   - 要说明触发模型、重连/会话变化、重新注册或使用 Curator Cache 的必要性。
3. **Session Expired 与网络短暂断开有什么业务差别？**
   - 会话失效可能导致临时节点消失和锁/领导权丢失；客户端应重新建立状态，不能假定原身份仍有效。
4. **为什么 ZooKeeper 不适合存业务大数据？**
   - 其定位是协调元数据；大载荷和高频写会放大内存、网络、复制和运维风险。
5. **分布式锁的正确性依赖什么？**
   - 获取/释放、会话、超时、异常路径和业务幂等都要考虑；锁不是事务，也不自动处理外部副作用。
6. **Leader 选举后为何还要做幂等？**
   - 领导权切换与任务执行不是同一个原子操作，网络和进程故障可能造成重复或不确定结果。
7. **ACL 应该如何设计？**
   - 最小权限、按路径隔离、避免开放 ACL、凭证不写入代码/日志，并建立访问方清单和变更审计。
8. **如何排查客户端收不到配置变更？**
   - 依次查路径、节点版本、连接/会话、Watcher/Cache 注册、ACL、服务端日志和客户端重连状态。

## 七、AI 协作方式：可辅助设计，不能替代故障演练

AI 可帮助把需求转换为 ZNode 树、列出节点生命周期、生成单元/集成测试清单、解释 Curator API 和根据匿名日志归类故障。人工必须确认真实路径、ACL、连接地址、任务幂等语义、会话超时和生产变更窗口。

```text
请审阅一个 ZooKeeper 协调设计，不输出真实连接串或账号。
业务目标：<配置监听/选主/锁>；参与实例：<数量>；
节点路径和类型：<草案>；会话超时与重试：<草案>；
外部副作用：<数据库写入/任务执行>。
请指出：会话失效、重复执行、Watcher 重新注册、ACL、关闭顺序的风险，
并给出测试场景。不要假设选主或加锁后自动满足 Exactly Once。
```

AI 给出的设计必须在至少两个客户端和一次故障切换中验证；只做单客户端 happy path 无法证明协调逻辑可用。

## 八、现有资料缺口与下一步

| 缺口 | 对求职的影响 | 建议补齐方式 |
| --- | --- | --- |
| 缺少可运行的多客户端项目 | 难以证明会话、监听和选主不是纸面理解 | 增加 Curator 小项目和两/三实例演练说明 |
| 缺少真实安全实践 | ACL 只停留在概念会被追问 | 在测试集群设计最小权限 ACL，保存脱敏验证结果 |
| 缺少故障与监控材料 | 平台岗位重视稳定性，不只重视 API | 记录一次断连、Session 失效或节点恢复的日志与结论 |
| 缺少与大数据组件的实际关系 | 容易无法回答“为什么需要它” | 梳理具体 Kafka/Flink/调度组件版本与依赖方式，不能凭名称猜测 |
| 缺少替代方案的选型依据 | 面试会问为什么不用数据库、Redis 或其他协调组件 | 对比一致性、延迟、运维、业务副作用和团队现状，写出场景化取舍 |

## 九、投递前自查

- 能画出一个配置/选主/锁的节点树，并解释每个节点类型。
- 至少能复现一次客户端断连、临时节点消失、重连或 Leader 切换。
- 知道 Watcher、锁和选主各自不能保证什么。
- 简历中没有暴露连接串、节点 IP、账号、ACL 凭据或真实集群拓扑。
- 能把 ZooKeeper 定位为分布式系统与数据平台的辅助基础能力，而不是强行包装成 AI 算法核心。
