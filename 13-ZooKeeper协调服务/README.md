# ZooKeeper 协调服务

Apache ZooKeeper 是分布式应用的协调服务，提供配置管理、命名服务、分布式锁等核心功能。本章节涵盖 ZooKeeper 概念、安装部署、集群搭建及 Java 客户端使用。

## 适用场景

- 分布式服务需要保存少量协调元数据，例如服务注册、配置、节点存活或任务归属。
- 多个实例需要通过临时节点、顺序节点或 Watch 机制协调访问顺序。
- 需要理解基于 ZooKeeper 的分布式锁、集群成员感知和故障切换的基础行为。

## 学习与实践路径

1. 先在单机环境启动服务，用命令行创建、读取、更新和删除测试节点，区分持久、临时和顺序节点。
2. 使用两个客户端观察会话断开、临时节点消失和 Watch 触发，理解通知不是永久订阅的行为。
3. 按集群搭建文档完成小规模集群，检查每台节点的身份、数据目录、网络连通和运行日志。
4. 使用 Java 客户端实现一个最小的配置读取、节点监听或协调示例，明确连接超时、会话超时、重试和关闭逻辑。
5. 将示例映射到实际业务时，先评估节点数量、变更频率、权限和故障恢复；协调服务不应承载大数据量或高频业务数据。

## 常见产出

- ZooKeeper 集群节点清单、配置说明、数据目录与备份恢复步骤。
- ZNode 命名规范、节点层级图、数据格式、ACL 和访问方清单。
- Java 客户端连接配置、重试策略、监听处理与关闭流程说明。
- 分布式锁或服务协调的时序图、异常路径和监控/排障手册。

## 维护建议

- 生产集群通常使用奇数个节点形成多数派，并持续关注节点在线状态、磁盘、延迟和会话异常。
- ZNode 数据要保持小而清晰，节点路径与数据格式属于接口契约，变更前应评估全部客户端。
- Watch 触发后需要按客户端模型重新注册；会话失效、网络抖动和重连行为必须在测试环境演练。
- 高风险 Shell 操作先确认目标路径和环境，ACL、身份认证、数据目录和日志中不得泄露敏感信息。
