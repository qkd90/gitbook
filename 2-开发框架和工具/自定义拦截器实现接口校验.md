# 自定义拦截器实现接口校验

## 使用场景

拦截器适合处理横切逻辑，例如登录态校验、接口签名、租户上下文、请求日志、灰度标记、幂等校验等。它不适合承载具体业务逻辑，业务判断仍应放在 service 层。

常见流程：

```text
请求进入
  ↓
拦截器读取 header、token、签名、时间戳
  ↓
校验身份和请求合法性
  ↓
写入用户上下文或拒绝请求
  ↓
进入 Controller
```

## HandlerInterceptor 示例

```java
@Component
public class ApiAuthInterceptor implements HandlerInterceptor {

    private static final String TOKEN_HEADER = "Authorization";

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws Exception {
        String token = request.getHeader(TOKEN_HEADER);
        if (!StringUtils.hasText(token)) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            response.setContentType("application/json;charset=UTF-8");
            response.getWriter().write("{\"code\":401,\"msg\":\"未登录或登录已过期\"}");
            return false;
        }

        // 这里可以根据 token 查询用户信息，并放入 ThreadLocal 或 request attribute。
        request.setAttribute("token", token);
        return true;
    }
}
```

## 注册拦截器

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    private final ApiAuthInterceptor apiAuthInterceptor;

    public WebMvcConfig(ApiAuthInterceptor apiAuthInterceptor) {
        this.apiAuthInterceptor = apiAuthInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(apiAuthInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns(
                        "/api/login",
                        "/api/logout",
                        "/api/health"
                );
    }
}
```

## 接口签名校验思路

签名校验通常包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `appId` | 调用方身份 |
| `timestamp` | 请求时间戳，用于防重放 |
| `nonce` | 随机串，用于防重复请求 |
| `sign` | 请求签名 |

签名原文可以按固定顺序拼接：

```text
appId=xxx&nonce=yyy&timestamp=1710000000000&body=请求体&secret=密钥
```

校验步骤：

1. 判断 `appId` 是否存在。
2. 根据 `appId` 查询密钥。
3. 判断 `timestamp` 是否超过允许时间窗口。
4. 判断 `nonce` 是否已使用，已使用则拒绝。
5. 重新计算签名并与请求签名比对。
6. 校验通过后放行。

## 注意事项

- 拦截器中不要读取请求体后不回写，否则 Controller 可能读不到 body。
- 签名算法、参数排序、字符编码必须前后端保持一致。
- token、密钥、手机号等敏感信息不要直接打印到日志。
- 对外接口要考虑重放攻击，建议加入 `timestamp` 和 `nonce`。
- 权限判断可以在拦截器做粗粒度校验，细粒度数据权限仍放在业务层。

## 常见问题

### OPTIONS 请求被拦截

跨域预检请求使用 `OPTIONS` 方法，通常不携带业务 token。可以在拦截器中直接放行：

```java
if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
    return true;
}
```

### 返回中文乱码

设置响应编码：

```java
response.setContentType("application/json;charset=UTF-8");
```

### Controller 获取不到用户信息

确认拦截器已经注册，并且路径匹配规则包含当前接口。可以在 `preHandle` 中打印请求路径辅助定位。
