# 开发框架和工具

## 章节定位

本章节整理后端工程开发中常用的框架、工具链和项目规范，重点解决“如何把 Java 代码组织成可维护的后端项目”。

## 适用场景

- 从零创建或接手一个 Spring Boot 后端项目，需要快速确认本地开发、构建和协作方式。
- 需要统一接口返回、异常处理、权限校验、日志与项目包结构，降低多人协作成本。
- 排查“本地能跑、环境不一致”“接口异常难定位”“日志难检索”等工程问题。
- 为业务模块接入 MyBatis-Plus、MongoTemplate、租户或数据权限等现有能力时寻找参考入口。

## 一条工程实践路径

```text
本地环境与构建
  ↓
项目结构与配置管理
  ↓
接口返回、异常处理和访问校验
  ↓
数据访问与业务模块实现
  ↓
日志、权限、环境隔离与协作流程
```

建议先将“能启动”提升为“容易维护”：每进入一个新项目，先明确启动配置、模块职责、接口约定和日志位置，再开始叠加业务功能。

## 实战要求

每个后端项目至少应该具备：

- 清晰的包结构。
- 统一异常和统一返回。
- 参数校验。
- 日志规范。
- 数据库访问规范。
- 环境隔离配置。
- 接口联调和发布检查清单。

## 开发与发布检查清单

- 配置是否按环境拆分，是否避免把密码、令牌和生产地址写入代码或文档。
- 新接口是否复用统一异常、返回和校验约定，而不是为单个接口另起一套格式。
- 新增组件或依赖注入前，是否已阅读同模块中最相近的实现与配置。
- 数据访问是否明确事务边界、空值处理、分页与批量操作的影响范围。
- 日志是否保留请求或业务定位所需的上下文，同时避免记录敏感信息。
- 提交前是否完成接口联调、关键异常路径验证，以及配置和日志的复查。

## 维护原则

- 本目录优先沉淀可复用的工程做法和排查步骤，业务系统特有规则应放在对应项目文档中。
- 同一类主题出现多份资料时，在入口页或标题中说明适用范围，避免把不同框架版本的写法混用。
- 记录命令、配置或截图时，去除真实账号、密钥、内网地址等敏感信息，并说明必要前置条件。
- 对“最佳实践”保留使用边界：优先遵循当前项目已稳定落地的约定，再参考通用示例。
