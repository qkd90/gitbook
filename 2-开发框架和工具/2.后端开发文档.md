# 后端开发文档

## 开发目标

后端开发文档用于统一接口设计、代码分层、异常处理、数据库访问、日志记录和发布验证方式。团队协作时，文档应能让新成员快速理解项目如何开发、如何联调、如何排查问题。

## 标准开发流程

1. 明确需求边界：接口入参、返回字段、权限要求、数据范围、异常场景。
2. 设计数据模型：表结构、索引、枚举值、逻辑删除、创建更新时间。
3. 设计接口协议：URL、HTTP 方法、请求体、响应结构、错误码。
4. 编写业务代码：Controller 保持轻量，Service 处理业务，Mapper 负责数据访问。
5. 编写测试和联调：单元测试、接口测试、边界值测试。
6. 发布验证：启动日志、健康检查、核心接口、数据库变更确认。

## 分层建议

```text
controller
  └─ 接收参数、参数校验、调用 service、返回结果

service
  └─ 业务编排、事务控制、权限判断、事件发送

mapper/repository
  └─ 数据库查询、更新、复杂 SQL

domain/entity
  └─ 数据库实体、业务对象

dto/vo
  └─ 接口入参、出参、内部传输对象
```

## 接口设计规范

### URL 命名

```text
GET    /users              查询列表
GET    /users/{id}         查询详情
POST   /users              新增
PUT    /users/{id}         更新
DELETE /users/{id}         删除
POST   /users/import       导入
GET    /users/export       导出
```

### 请求参数

- 查询参数使用 `Query` 或 `Req` 后缀。
- 新增和更新参数尽量分开，避免更新接口误传创建字段。
- 必填字段加校验注解，枚举值在文档中列清楚。
- 时间字段统一格式，例如 `yyyy-MM-dd HH:mm:ss`。

### 返回结构

返回字段要稳定，避免频繁删除或改名。分页接口建议明确以下字段：

```json
{
  "total": 100,
  "rows": [],
  "code": 200,
  "msg": "操作成功"
}
```

## 业务代码要点

### 参数校验

```java
@PostMapping("/users")
public R<Void> add(@Validated @RequestBody UserAddReq req) {
    userService.add(req);
    return R.ok();
}
```

### 事务边界

涉及多表写入时，事务应放在 service 层。

```java
@Transactional(rollbackFor = Exception.class)
public void submitOrder(OrderSubmitReq req) {
    // 校验库存
    // 创建订单
    // 扣减库存
    // 发送事件
}
```

### 异常处理

业务异常要包含清晰提示，系统异常保留日志。

```java
if (user == null) {
    throw new ServiceException("用户不存在");
}
```

## 数据库开发

### 建表关注点

- 主键类型和生成策略。
- 字段长度、默认值、是否允许为空。
- 业务唯一约束。
- 查询字段索引。
- `create_time`、`update_time`、`create_by`、`update_by`。
- 逻辑删除字段。

### SQL 编写建议

- 列名不要使用 `select *`，重要接口显式列出字段。
- 查询条件要考虑索引命中。
- 批量操作控制数量，避免一次处理过多数据。
- 复杂 SQL 要补充说明业务含义。

## 联调清单

- 接口路径和请求方法是否一致。
- token、租户、部门、用户上下文是否正确。
- 必填字段缺失时是否返回明确错误。
- 无数据、单条数据、多条数据、大量数据是否正常。
- 重复提交、越权访问、非法 ID 是否处理。
- 数据库事务失败后是否回滚。

## 发布检查

- 数据库脚本已执行并可回滚。
- 配置项已在目标环境准备。
- 日志目录有写入权限。
- 启动后健康检查通过。
- 核心接口通过 Postman 或自动化用例验证。
- 监控和告警指标正常。
