# Hive 数据仓库

Hive 是基于 Hadoop 的数据仓库工具，提供类 SQL 查询语言（HiveQL）来简化大数据处理。本章节涵盖 Hive 的核心概念、安装部署、DDL/DML 操作及查询优化。

```
                                           ↓

```

## 适用场景

- 需要用 SQL 对 HDFS 上的离线数据建表、清洗、汇总和分析。
- 需要将业务口径沉淀为可审阅的表结构、分区策略和查询脚本。
- 需要为报表、离线指标或下游 Spark/Flink 任务提供稳定的数据模型与数据集。

## 学习与实践路径

1. 先完成一次 Hive 环境验证，确认 Hive 服务、元数据存储和 HDFS 的连接关系。
2. 为一份小型原始数据设计数据库、明细表和查询视图，使用 DDL 固化字段、类型、注释和存储约定。
3. 用 DML 导入或写入数据，并围绕业务日期建立分区；分桶只在数据规模和查询方式确实需要时使用。
4. 编写包含过滤、聚合、关联和窗口函数的指标查询，使用实际数据量验证口径、空值和重复数据的处理。
5. 对慢查询记录扫描范围、分区裁剪、文件规模和执行计划观察结果，再决定是否调整模型或 SQL。

## 常见产出

- 数据库、表、视图和字段的数据字典，以及层级、粒度、主键和更新方式说明。
- 可重复执行的 DDL、DML、初始化数据和指标 SQL 脚本。
- 分区与分桶设计、业务日期口径、补数方案和历史数据保留策略。
- 指标校验结果、查询性能记录和常见异常排查清单。

## 维护建议

- 表结构变更要先评估历史数据、下游 SQL、报表和接口消费者，避免字段语义悄然改变。
- 分区需要设置生成、校验、补数和过期策略；不要把分区数量和小文件问题留到数据量扩大后再处理。
- 业务口径、时区、统计周期和去重规则必须与 SQL 一起维护，避免“同名指标不同结果”。
- 生产查询优先限定分区和字段范围；测试、临时分析与正式产出应分开，避免误写或误删正式数据。
