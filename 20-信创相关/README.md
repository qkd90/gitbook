# 信创相关

## 章节定位

本章节整理国产数据库和信创环境适配经验，当前覆盖达梦、OceanBase、openGauss。重点是把“安装成功”推进到“应用可迁移、数据可验证、性能与运维可交接”的完整过程。

适用于新环境部署、数据库选型调研、Java 应用数据库迁移、SQL 兼容改造和上线前验证。

## 推荐迁移与实践路径

1. **确定范围与基线**：记录源/目标数据库版本、操作系统、驱动版本、数据量、业务模块、停机窗口和回滚边界。
2. **完成环境验证**：先依据对应数据库文档检查软硬件条件、安装状态、服务启动、客户端连接和 JDBC 配置。
3. **梳理兼容差异**：对表结构、字段类型、主键/自增/序列、分页、日期/字符串函数、SQL 方言和导入导出逐项建立清单。
4. **从小范围迁移开始**：先在测试环境迁移代表性表和脱敏数据，验证建表、导入、查询、写入、事务和异常处理。
5. **验证性能与运维闭环**：核对索引、执行计划、连接池、备份恢复、监控告警和故障恢复步骤，再扩大迁移范围。
6. **保留验收证据**：记录迁移脚本、数据校验口径、问题清单、最终版本和回滚方案，避免仅凭“应用能启动”判断迁移完成。

## 迁移检查清单

- JDBC URL、驱动类、账号权限和连接池配置是否适配目标库。
- 字段类型、长度、默认值、空值、主键、自增和序列是否保持业务语义。
- 分页 SQL、日期函数、字符串函数、聚合/排序及复杂 SQL 是否在目标库执行正确。
- 表结构、索引、约束、视图、存储过程等对象是否按实际使用范围完成迁移。
- 导入导出后的行数、关键字段、编码/字符集和时间数据是否一致。
- 核心查询的执行计划、耗时和连接数是否符合预期。
- 备份、恢复、监控、告警和回滚是否已有经过验证的操作步骤。

## 常见问题定位顺序

1. 先确认数据库服务、网络、账号权限和 JDBC 连接是否正常。
2. 再检查 SQL 方言、数据类型、函数、分页和序列/自增差异。
3. 数据异常时，按表结构、导入日志、记录数、关键字段和字符集逐层比对。
4. 性能问题先查看索引、执行计划、连接池和资源配置，不直接将源库经验套用到目标库。

## 后续维护方向

- 每篇数据库文章应标注数据库版本、操作系统、驱动版本、适用范围和验证环境。
- 迁移记录应区分“已验证的命令/结论”和“待验证的假设”，避免跨版本直接复用。
- 示例配置使用占位符，不记录真实账号、密码、连接串、业务数据或生产拓扑。
