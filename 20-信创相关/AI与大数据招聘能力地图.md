# AI 与大数据招聘能力地图

> 本页依据本目录现有的 [达梦数据库](达梦数据库.md)、[OceanBase数据库](OceanBase数据库.md) 和 [openGauss数据库](openGauss数据库.md) 资料整理。它强调国产化环境适配、数据库迁移与数据服务稳定性，适合作为大数据/数据平台/AI 平台的基础设施补充；它不是模型训练、算法创新或完整 DBA 生产经验的替代品。

## 一、岗位定位：信创数据库能力如何连接 AI 与大数据

| 岗位方向 | 关联程度 | 本目录可证明的准备方向 | 不应越界的说法 |
| --- | --- | --- | --- |
| 数据平台工程师 | 高 | 数据库环境评估、迁移验证、兼容性清单、备份/回滚意识 | 未经真实项目验证，不宣称完成全量生产迁移 |
| 大数据开发工程师 | 中高 | 结果库、元数据、数据服务和国产化部署适配 | 数仓计算核心仍需要 SQL、Spark/Flink、调度和建模能力 |
| AI 平台 / MLOps 工程师 | 中 | 模型元数据、任务状态、特征/结果服务可能依赖数据库；关注安全和可靠性 | 不把数据库安装经验说成模型平台建设经验 |
| Java 后端 / 数据迁移工程师 | 高 | JDBC、SQL 兼容、表结构、事务、导入导出、性能验证 | 不能只凭“服务能连上”说迁移完成 |
| 算法/模型工程师 | 低（辅助） | 知道模型服务的数据依赖、权限、审计和落库风险 | 不替代 Python、模型、实验、特征和评估能力 |

信创数据库在招聘中的加分点是：能从操作系统、资源、驱动、SQL、数据校验、性能、备份恢复和回滚一起考虑，避免把“能安装”误判为“能上线”。

## 四、可交付实战项目

### 项目一：跨数据库 SQL 兼容性与数据契约检查器

**场景：**为一个匿名的业务表集合准备从源库迁移到目标国产数据库的兼容性测试，不直接迁移生产数据。重点是将“兼容”拆成结构、语法、事务、结果和性能五类可验证问题。

**应交付：**

- 表/字段清单：类型、长度、默认值、空值、主键、唯一约束、索引、序列/自增、时间/字符集语义。
- SQL 用例集：建表、插入、更新、删除、分页、日期/字符串函数、聚合、排序、关联、事务提交/回滚和异常输入。
- 执行结果矩阵：源库/目标库的成功失败、返回行数、关键字段、执行计划/耗时（在同等测试条件下）。
- 兼容性分类：可直接运行、需改写、不可支持、待确认；每项附原因、影响范围和替代方案。
- 安全说明：连接信息由环境变量/安全配置管理，测试数据匿名化，日志不记录密码和完整业务内容。

**验收点：**任何“迁移成功”的结论都能追溯到具体 DDL/DML 和对账结果；发现 SQL 差异时能说明是函数、类型、分页、事务还是索引/执行计划问题，而不是只说“报错了”。

### 项目二：数据库迁移与回滚的最小演练

**场景：**在两个本地/测试库之间迁移一个小型匿名主题域，例如用户偏好、设备状态或指标结果表；覆盖空表、正常数据、重复主键、空值、时间字段和特殊字符。

```text
源库匿名数据
  → 导出前基线（行数/校验/关键聚合）
  → 目标库建表与导入
  → DDL/DML/事务/查询验证
  → 对账与性能基线
  → 回滚或恢复演练
```

**应交付：**

- 迁移范围、源/目标版本、驱动、停机/切换边界和回滚条件。
- 导入/导出步骤和失败重试策略；明确是全量迁移、增量同步还是仅验证样本。
- 对账脚本：总行数、主键覆盖、空值、关键字段哈希/聚合、日期范围和编码问题。
- 应用接入验证：JDBC 连接、连接池、读写、事务、异常处理和只读/写入权限。
- 回滚手册：何时停止切换、如何恢复源服务、如何处理目标库已写入数据。

**验收点：**可从空环境按文档重做；一次失败导入不会产生无法识别的重复数据；回滚步骤明确且在测试环境演练过。

### 项目三：面向 AI/数据服务的数据库就绪度清单

**场景：**为模型结果、任务元数据、特征服务或 BI 结果库设计数据库接入前检查。此项目强调平台边界，不把数据库当成训练框架。

**应交付：**

- 读写模式、峰值连接、数据增长、保留周期、索引和分区/分表假设。
- 数据类型契约：模型版本、请求 ID、时间、结果状态、错误信息的字段长度/编码/空值规则。
- 性能基线：代表性查询、并发/连接池假设、慢查询阈值和资源监控项。
- 合规边界：训练数据、原始输入、可识别信息是否允许落库，谁有读取权限，如何脱敏/审计/清理。
- 故障策略：数据库不可用时服务如何降级、重试是否幂等、写入是否会重复、如何告警和恢复。

## 五、简历表达：体现迁移验证能力

| 能力点 | 建议的表述（完成后） | 需准备的佐证 |
| --- | --- | --- |
| 环境适配 | “完成国产数据库部署前的 OS、CPU、内存、磁盘、文件系统、网络和驱动基线检查。” | 环境检查表、版本与风险记录 |
| SQL 兼容 | “建立 DDL/DML、分页、函数、事务和索引的兼容性用例集，分类记录改写与验证结果。” | 用例矩阵、执行输出、差异说明 |
| 数据迁移 | “对匿名数据执行建表、导入、关键字段/聚合对账和回滚演练，明确全量/增量边界。” | 迁移文档、对账脚本、回滚记录 |
| 性能与运维 | “为结果库/数据服务定义连接、索引、慢查询、备份恢复和告警检查项。” | 性能基线、监控清单、故障演练 |
| AI 平台辅助 | “为模型结果/任务元数据服务梳理数据契约、权限、保留和幂等写入风险。” | 表设计、接口契约、脱敏/权限说明 |

不要仅写“熟悉达梦、OceanBase、openGauss”。更有说服力的是写清“在什么版本/测试环境、针对什么迁移范围、用什么对账规则验证了什么结果”，同时避免泄露组织名称、服务器地址和账号信息。

## 六、面试要点：回答要覆盖数据而非只覆盖安装

1. **为什么应用能连上目标库并不代表迁移完成？**
   - 还要验证表结构、数据、SQL、事务、编码、性能、备份恢复和切换/回滚。
2. **如何发现数据迁移后的隐性错误？**
   - 除行数外，对主键覆盖、空值、关键聚合、哈希/抽样、日期范围、字符集和异常记录逐项对账。
3. **主键、自增/序列迁移最容易遗漏什么？**
   - 新写入后的取值、并发插入、序列起始值、重复主键和回滚后的状态都要测。
4. **SQL 兼容性如何系统化验证？**
   - 按 DDL、DML、函数、分页、事务、索引、视图/存储过程、权限分组，不能只改一条报错 SQL。
5. **数据库性能问题如何定位？**
   - 先确认查询模式、数据量、索引、执行计划、连接池、资源和并发，再考虑参数；不能照搬源库经验。
6. **迁移/切换如何设计回滚？**
   - 切换前定义数据冻结/双写/同步边界、回滚条件、源库保留和目标库写入处理，先在测试环境演练。
7. **AI/模型服务将结果落库时有哪些风险？**
   - 请求重复、模型版本不明、字段长度、隐私数据、权限、保留期限、慢写和数据库不可用降级都要考虑。
8. **为什么信创数据库技能与 AI 有关但不是算法核心？**
   - 它解决运行环境和数据服务可靠性；模型效果仍取决于数据、特征、训练、评估和业务验证。

## 七、AI 协作方式：用 AI 做差异清单，不能让它替代数据库验证

AI 可以协助把匿名 DDL/SQL 分类、从报错中提出兼容性假设、生成对账用例、整理迁移检查单和起草回滚文档。人工必须在目标版本的真实测试库中执行和核验，尤其要确认 SQL 语义、事务、数据范围、权限和性能。

```text
请评审一组已脱敏的数据库迁移材料。
源/目标版本：<版本>；对象：<表/索引/SQL 类型>；数据规模：<测试规模>；
目标：<安装/兼容/迁移/性能/回滚>。
请输出：兼容风险、需要的测试用例、对账字段、回滚前提和不应自动执行的操作。
不得生成真实密码、连接串、无条件 DELETE/UPDATE 或未经证实的数据库语法。
```

AI 给出的 SQL 只能作为草稿；任何结构迁移、数据覆盖、账号/权限变更都要先在隔离环境审查并备份。

## 八、现有资料缺口与下一步

| 当前缺口 | 招聘风险 | 下一步可验证动作 |
| --- | --- | --- |
| 资料以安装和资源说明为主 | 无法证明兼容改造、迁移或性能能力 | 建立匿名 schema 和跨库 SQL 用例仓库 |
| 缺少版本、驱动和 JDBC 实测记录 | 不同版本兼容差异可能很大 | 对每次实验记录 OS/DB/驱动/客户端版本 |
| 缺少完整导入、对账和回滚脚本 | 面试会追问数据正确性和切换风险 | 完成一个小型迁移演练并保留可重跑证据 |
| 缺少高可用/备份恢复案例 | 数据平台岗位关注故障恢复 | 补充测试库备份、恢复、主机故障或服务不可用演练 |
| 缺少数据服务/AI 平台连接案例 | 容易只停留在 DBA 安装层 | 用一个结果库/API Demo 验证表设计、幂等写入和权限 |

## 九、投递前自查

- 能用“环境—兼容—迁移—对账—性能—回滚”讲完整个任务，不止讲安装命令。
- 所有数据库结论有测试版本、范围和命令/输出证据，生产经验和测试经验不混写。
- 没有在 GitBook、简历、代码或截图中泄露密码、连接串、账号、IP、真实表名或业务数据。
- 能说明信创数据库在数据平台/AI 应用中的基础设施作用，也能坦诚其不替代模型和大数据计算能力。
